# EKdelta 開發筆記

> **目前版本：1.2.5／CP185。** 本文件說明公開版本的來源結構、維護約定與驗證邊界。

EKdelta 是可在本機使用的 Markdown 編輯器，提供一般筆記、臺灣碩博士論文與 REVTeX 國際期刊稿件三種寫作流程。正常啟動時應顯示六份內建文件、選單與編輯畫面；只有外框而沒有文件的畫面，代表啟動未完成，不能視為測試通過。

## 本版維護重點

- 「關於」改為簡短用途與命名介紹；依作者指定署名 Jason Chen。
- 臺灣論文語法工具列按鈕固定顯示 `TW`；完整名稱保留在中英文提示中，內部 `twthesis` 識別字不變。
- 修正兩份論文模板示意圖缺少右括號的 Markdown 語法；審定書圖片預設留空，交由使用者填入自己的檔案。
- AI 交接包採 00–08 角色分工，僅保留根目錄一份可執行產品；桌面副本、暫存與測試 log 不封裝。
- 1.2.2 的啟動修復與安全命名原則繼續有效，完整工程決策與待辦見交接包的 03／04／06 文件。

```bash
python3 build.py
```

建置器偵測到 `08_測試工具/EKdelta` 結構時，預設直接產生交接包根目錄的 `02_目前程式碼_v1.2.5.html`；獨立 source 則產生 `EKdelta_v1.2.5.html`。

建置後以產物中的版本、腳本與文件內容為驗證對象。相同來源重建後應得到相同位元組與雜湊；只檢查建置器能執行，不能證明產品能啟動。發行時同步 `APP_VERSION`、`APP_CHECKPOINT`、產品中繼資料、版本資訊、文件及產物資訊。

| 工具列短標籤 | TW（中英文共用） |
| JavaScript 變數與屬性 | `twthesis`、`twthesisEn`、`twthesisLogo` 等合法識別字 |
| JavaScript 常數 | `TW_THESIS_*` |
| CSS 類別、HTML 屬性值與 Markdown 圍欄 | `twthesis-*` |
| 資料夾同步快照 | `ekdeta-data.json` |
| 機器名稱（不隨產品改名） | 儲存鍵 `ekdeta`、IndexedDB `ekdetaDB`、`ekdeta-data.json`、`ekdeta-backup.json`、表格註記 `ekdeta-html-table`、設定值 `ekdeta-loose`、設定與專案 schema `ekdeta-html-*`、剪貼簿格式 `application/x-ekdeta-html-markdown`、`ekdeta.*` 偏好鍵、桌面殼協定 `ekdeta://` 與 `__EKDETA_SHELL__`、`<meta name="ekdeta-*">` |

顯示文字、JavaScript 識別字與 Markdown 語法有不同的命名需求。含空格的顯示名稱不可直接當成 JavaScript 變數；`twthesis` 是 Taiwan Thesis 的機器用前綴；模式識別會正規化成小寫，因此前綴大小寫必須一致。含連字號的語法或 CSS 名稱應放在字串中，物件屬性若使用此格式必須加引號。改名時逐一核對宣告、讀寫、CSS 選擇器、儲存資料與匯出入口，並維持同一功能的名稱一致。

1.2.4 把產品名稱改為 EKdelta 時只改顯示文字（選單、視窗標題、關於、說明文件、匯出檔案裡的註記）。上表「機器名稱」一列保留 `ekdeta`：它們存在使用者的瀏覽器、資料夾與文件裡，或由桌面殼與嵌入 EKdelta 的網頁讀取，改掉會讓既有文件讀不到、桌面殼找不到引擎、嵌入它的網頁失去連接。

## 資料與編輯約定

- Markdown 原始文字是文件內容的依據。顯示、分頁、公式預覽與匯出不得在沒有編輯操作時偷偷改寫原稿。
- 一般文件使用目前瀏覽器的本機儲存；連結資料夾後另保存 Markdown 與 `ekdeta-data.json`。內建文件不當成使用者檔案重複保存。
- 一般段落、行內編輯、表格、原始碼與浮動編輯框共用格式操作入口。執行工具列命令前保留選取位置，無法安全定位時取消操作。
- 原始碼文字、語法著色與行號共用字體及幾何設定；復原與重做必須作用於目前的編輯宿主。
- 切換文件、模式或語言時，先處理目前編輯，再更新畫面。重建分屏或工具面板時釋放觀察器、拖曳事件、計時器與已失效的 DOM 參照。

## 三種寫作流程的邊界

一般 Markdown 負責連續文字編輯；臺灣論文負責 A4 頁面、封面、目錄、章節與圖表編號；REVTeX 使用獨立 TeX 編譯與 PDF 預覽。修改其中一路時，要確認另外兩路沒有誤用其樣式、字體或分頁設定。

臺灣論文語法包括 `twthesis-titlepage`、`twthesis-titleback`、`twthesis-approval`、`twthesis-toc`、`twthesis-lof`、`twthesis-lot` 與 `twthesis-appendix`。模板、表單產生器、語法辨識、畫面渲染與 HTML／PDF 匯出必須使用同一套語法。

學校格式屬於模板與版型設定。範例包含國立中山大學欄位，使用者仍需依各校與系所的提交規範確認封面、字體、頁邊距、頁碼、審定書及目錄。

## PDF 與批次輸出約定

- 每批可選 10／25／50／100 頁，預設 50 頁。同一批次工作先建立分頁與索引，每批只建立所需的列印文件。
- `afterprint` 只表示列印介面可能返回，不能代表 PDF 已成功儲存。保存狀態由使用者確認，取消或重印不應誤記成完成。
- 清理上一批的列印內容、圖片、樣式、事件及 iframe 後才允許下一批。列印期間設定含頁數範圍的檔名，結束後恢復原視窗標題。
- 實體頁次、頁碼與章節／公式／圖表編號保留原文件順序。同批目錄可保留連結，跨批目標只保留文字；各批 PDF 由使用者自行合併。
- 顯示公式的主體維持置中，編號位於可用區塊右側；共用 PDF 樣式要包含公式編號布局。短公式、長公式與手動 `\tag{...}` 都要確認不重疊。
- REVTeX 使用 TeX 產生的 PDF 與專案匯出，不能誤進入臺灣論文的頁面複製或分批列印流程。

## 回歸檢查範圍

發行檢查應涵蓋以下實際入口，並記錄每項使用的環境與結果：

1. **啟動與文件**：檢查組裝後全部應用腳本、啟動錯誤、六份內建文件、模板副本、儲存／還原與語言切換。
2. **可見介面**：九組選單、關於、版本資訊、偏好設定各分頁、快捷鍵、工具列、尋找／取代、圖片修復、表格與公式面板。
3. **文字與語法**：大小寫名稱掃描，另檢查模板內的團隊全名、個資與隱藏註解。檢查 Markdown、CSS、JavaScript 與輸出文字的對應。
4. **版型與輸出**：一般 Markdown、臺灣論文中英文電子／紙本版、REVTeX、原始碼模式；確認頁碼、公式、目錄、封面與圖片。
5. **生命週期**：切換模式、關閉分屏、重建面板、取消列印、重印與多批輸出，避免重複事件或殘留資源。

套件完整性雜湊、字體或圖片的 base64 資料，以及第三方數學符號名稱可能偶然包含短字串。掃描命中要檢查上下文；不得為了讓搜尋結果歸零而破壞資產或第三方程式。

## 驗證邊界與後續維護

本版的靜態檢查、來源重建與受控執行結果，只能證明各自檢查的範圍。這次環境未完成原生瀏覽器互動畫面、macOS／Electron 原生列印、完整 PDF 版面、外部 TeX Engine Pack、安裝器簽章與公證的實機驗證。發行報告應分別列出已執行與尚未執行的項目。

特別是超長文件的連續列印，通過批次狀態機測試不代表已完成實際記憶體壓力測試。後續以合成長文件測試分批 50／100 頁、取消、重印與多次開關列印視窗，並保存可重現的結果。

維護時優先確認保存成功狀態、HTML 匯出公式樣式、不同期刊前置區塊、全文參考定義更新與工具面板資源釋放。任何行為調整都應說明影響的模式與入口，避免只靠語法檢查判定完成。

## 與嵌入它的網站分開

EKdelta 是公開發布的獨立軟體，任何人都可以下載單一 HTML 使用。若有網站把它嵌進自己的頁面（例如某個實驗室的教學網站），網站需要的功能——帳號存檔、導覽、用量提示、語言與深淺色同步——一律寫在網站自己的轉接程式裡，透過上表的機器名稱與公開函式呼叫 EKdelta；不要為了某個網站修改 EKdelta，也不要在程式、內建文件或版本資訊裡寫特定網站的名稱。只有不論在哪裡使用都會發生的問題，才在 EKdelta 修。機器名稱與公開函式改名前，要先想到這些外部使用者。

## 影子編譯（1.2.5）

國際論文右側的自動編譯由 `src/scripts/21.js`（協調器）與 `22.js`（畫面）負責：

- 內容簽章包含「正在編輯、尚未提交的那一段」：照 `commitMathEdit()` 的算法試算，只讀不寫，輸入法組字中不算。
- 內容明顯沒打完（`$$` 不成對、程式碼區塊未收尾）時暫不編譯，送出 `orch:hold`。
- LaTeX 失敗只增加等待時間（800 → 6400 ms），保留最後一次成功的結果（`getLastGood()`）；只有引擎層失敗（沒有引擎、例外）連續三次才關閉自動編譯並送出 `orch:suspend`。
- 內容回到最後一次成功編譯的簽章時送出 `orch:recovered`，畫面清除錯誤提示；過期的失敗結果不顯示。
- 寬度不足以左右並排（扣掉檔案欄少於 640 px）時改上下排列，手機寬度收起檔案欄。
